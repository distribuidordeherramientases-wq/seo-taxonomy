# Manual de usuario de SEO Taxonomy

> Base documental: interfaz actual de la rama staging. Revisión: 26/09/2026.

Este manual explica la interfaz que ve un administrador de WordPress: menús, pestañas, campos, selectores, botones, casillas de verificación, tablas, estados y consecuencias de cada acción. La documentación conceptual de la Wiki se conserva como introducción; estas páginas constituyen el manual operativo.

## Convenciones

- **[Consulta]** lee o filtra datos sin cambiar el catálogo.
- **[Guarda]** almacena configuración, contenido o asignaciones.
- **[Modifica]** cambia datos existentes.
- **[Elimina]** borra, desactiva o retira información.
- **[Proceso]** inicia, pausa, reanuda o controla trabajo en segundo plano.
- **[API]** utiliza un servicio externo o puede consumir cuota.
- **[Exporta]** genera un archivo para revisión, copia o traslado.
- **[Producción]** puede afectar al frontal, pedidos o datos publicados.

Los campos de claves, tokens, usuarios y secretos se explican con ejemplos ficticios en **Conexiones y credenciales**. Nunca se publican credenciales reales en el manual.

## Regla de mantenimiento

Una función visible no se considera completamente documentada hasta que el manual indique:

- dónde se encuentra;
- para qué sirve;
- qué valores espera;
- qué hace cada botón, selector o checkbox;
- qué modifica;
- si consume una API o lanza un worker;
- qué riesgo tiene una acción destructiva;
- qué resultado debe esperar el usuario.

La rama staging es la fuente de esta documentación. Los cambios de estos archivos se sincronizan automáticamente con la GitHub Wiki.
